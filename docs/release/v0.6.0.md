# report-err v0.6.0 - Optimisation

**Measured, and faster where it fell behind.** v0.6.0 benchmarks report-err against anyhow, eyre, error-stack, and `Box<dyn Error>` on Linux x86_64, Windows x86_64, and Linux aarch64, fixes the rows where it was behind, and keeps every result in CI behind a 5% regression gate.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). It adds error codes with severity, category, and exit codes from define-err, a propagation trail, typed attachments, and notes and suggestions.

## What's in 0.6.0

- **Measured on three platforms.** Benchmarks B1 to B18 run in CI on Linux x86_64, Windows x86_64, and Linux aarch64, each one against the same operation written for anyhow, eyre, error-stack, or `Box<dyn Error>`. Every number, and every target met or missed, is in `docs/PERFORMANCE.md`.
- **Faster with context layers.** The extras (attachments, sections, trace points, and the rest) moved into a block of their own, so an error with only context layers allocates 192 bytes for them instead of 656. Dropping an error with three layers now takes 0.58 to 0.72 of anyhow's time (it was 1.00 to 1.30), and creating one 0.64 to 0.91.
- **A gate on every pull request.** Each pull request measures the base branch on the same runner and fails when report-err gets more than 5% slower.
- **Attachment budget.** A `String`, `Vec<u8>`, `Box<str>`, or `Box<[u8]>` attachment counts its heap bytes against `max_bytes`, so a large buffer cannot get past the budget by being small on the stack.
- **One-allocation messages measured, not adopted.** Formatting `err!("value {x}")` into one allocation was 11% slower on Linux x86_64 and not 20% faster anywhere.

## Where it is behind

`{:#}` (1.33 to 1.55 times anyhow) and `{:?}` (1.30 to 1.31) are slower than anyhow: report-err skips causes that repeat the layer before them and prints the location and trail. Creating an error on aarch64 is 8% to 26% slower. Each is on the list to fix before 1.0.

## Verified

- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows on every unit and integration test.
- The full gate on Windows and Linux, stable and Rust 1.81.

## Installation

```toml
[dependencies]
report-err = "0.6.0"
```

Rust 1.81 or newer. `no_std` with `alloc` works with `default-features = false`.
