# report-err v0.1.0 - Scaffold

**The repository and the plan.** v0.1.0 set up the crate in the portfolio template and wrote down the design before any code. There is no functional code in this release; it also claimed the name on crates.io.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. It keeps the `anyhow` API under the same names (`Error`, `Result`, `Context`, `bail!`, `ensure!`, a `source()` chain through every context layer), so moving from anyhow is a change of crate name, and adds error codes with severity, category, and exit codes, a propagation trace, typed attachments, notes and suggestions, several causes, suppressed errors, and a panic boundary. An error that only carries its cause and location is one allocation and one machine word, the same as anyhow.

## What's in 0.1.0

- The crate manifest: edition 2021, MSRV 1.81 (the same as define-err, the library report-err builds on), no dependencies, `Apache-2.0 OR MIT`, features `std` (default) and `testing`.
- The crate root: `VERSION`; `no_std` with `alloc`; `unsafe_code` denied, with the lints that will hold the future `unsafe` core to one documented module; missing docs and `unwrap`/`expect`/`panic`/indexing in library code denied; a clear build error on targets without atomic compare-and-swap.
- CI on Linux, macOS, and Windows, each on x86_64 and aarch64, on stable and 1.81; a `no_std` build for `thumbv7em-none-eabihf`; Miri with strict provenance under Stacked Borrows and Tree Borrows; loom; documentation in three feature modes; `cargo package`; `cargo audit` and `cargo deny`.
- `dev/PLAN.md`: purpose, scope, requirements, the one-word representation and its `unsafe` core with twelve invariants, the flat context store and how every layer still becomes a link of a real `source()` chain, the formatting rules, the API by tier and grade, a parity matrix against anyhow, eyre, error-stack, and snafu, sixteen threats with their tests and costs, performance targets, the testing plan, open decisions, and the decision log.
- `dev/DIRECTIVES.md` (engineering law and definition of done) and `dev/ROADMAP.md` (phases 0.2 to 1.0 with exit criteria).
