# report-err v0.4.0 - Codes and reports

**An error now says what it is, what to tell a client, and how the process should exit.** v0.4.0 adds error codes, severity, categories, and kinds from define-err; notes, warnings, and suggestions; typed attachments; a propagation trail; backtraces; and `ExitReport`, a `main` return type that exits with a code chosen from the error.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). From `0.5.0` it adds several causes, suppressed errors, and a panic boundary.

## What's in 0.4.0

- Codes: `code()` finds the innermost code in the chain with no extra call; `coded` sets one on an `Error`, a `Result`, or an `Option`; `err!`, `bail!`, and `ensure!` take a code first: `bail!(UserError::INACTIVE, "user {id} is inactive")`.
- `severity`, `category`, `kinds`, and their overrides. An `io::Error` root gets its category from its kind.
- `public_message`: text a client may see, from a catalog, a `from_info` root, or the category's default. It never comes from any `Display`, and it is `None` without a code.
- `configure_catalogs`: optional, once per process, so a code set by hand finds its title, severity, category, and public text.
- `from_info` and `info`: keeps per-value metadata such as a `retry_after` field.
- `note`, `warning`, `suggestion`; `attach` and `attachment::<T>()`; `trace()` and `trail()`; `backtrace()`.
- `ExitReport`: exits with `with_exit_code`, else the category's sysexits code, else 1. It escapes terminal and bidirectional controls in every message, cuts the report at 1 MiB, and keeps the right exit code when standard error is closed or broken.
- `Ok`, as in anyhow.

The allocation counts are exact and tested: a code, a severity, and an exit code cost nothing beyond the error, reading them allocates nothing, and the first attachment, section, or trace point costs one block.

## Verified

- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows on every unit and integration test.
- Exit status and standard error are checked by running a real process for each case, with escaping, a 2 MiB message, a broken pipe, and no reader at all. The backtrace variables are checked in child processes.

## Installation

```toml
[dependencies]
report-err = "0.4.0"
```

Rust 1.81 or newer. `no_std` with `alloc` works with `default-features = false`.
