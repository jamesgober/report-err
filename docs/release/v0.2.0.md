# report-err v0.2.0 - Design lock

**The public API, written down and approved.** v0.2.0 locked report-err's public API against define-err's locked API, settled every open decision, and measured the part of the design that carried the most risk: making every context layer a link of a real `source()` chain without giving up the one-word size or the allocation counts. There is still no functional code in this release; the anyhow surface ships in `0.3.0`.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. It keeps the `anyhow` API under the same names (`Error`, `Result`, `Context`, `bail!`, `ensure!`, `format_err!`, a `source()` chain through every context layer), so moving from anyhow is a change of crate name, and adds error codes with severity, category, and exit codes, a propagation trace, typed attachments, notes and suggestions, several causes, suppressed errors, and a panic boundary.

## What's in 0.2.0

- `docs/API.md`: the public API of 1.0, every item with its signature, behaviour, cost, examples, and the version it arrives in. The main type is `Error`, the ad-hoc macro is `err!` with `format_err!` as an alias, and `Error` dereferences to `dyn Error` with every context layer in its `source()` chain (new item ERR-19).
- `docs/UNSAFE.md`: the layout of the one-word representation, thirteen invariants of its `unsafe` core with the test for each, how the `source()` chain is built over the flat context store, and how Miri runs.
- `dev/PLAN.md`: the chain view measured on a prototype of the layout. One machine word and every allocation count stayed the same; a context layer grew from 32 to 40 bytes; creating an error with context stayed 1.5 to 2 times faster than anyhow; `chain()` walked 1.4 to 2.5 times faster than anyhow's; the prototype ran clean under Miri with strict provenance, under Stacked Borrows and Tree Borrows.
- Decisions: the one-word representation with every `unsafe` line in one module, and the macro name `err!`, both by James; every other open decision accepted as recommended; define-err's answers to report-err's four interface requests recorded (all accepted).
- define-err `0.2` became a dependency by published version (`default-features = false`, `alloc` on; report-err's `std` turns on define-err's). Its types are first used in `0.4.0`.

## What's next

`0.3.0` ships the anyhow surface: `Error`, `Result`, `Context` on `Result` and `Option`, `err!`, `format_err!`, `bail!`, `ensure!`, downcasting, `chain()`, `root_cause()`, `Deref` to `dyn Error`, the formatting rules, and `into_std` and `from_boxed`, with the `unsafe` core under Miri in CI.
