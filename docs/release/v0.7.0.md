# report-err v0.7.0 - Hardening

**Tested against attack.** v0.7.0 adds a test for every threat in the security plan, fuzzes the library for a day per target, and soaks it for 8 hours on Windows and Linux. The testing found three ways a misbehaving `Display` could hang report-err; all three are fixed.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). It adds error codes with severity, category, and exit codes from define-err, a propagation trail, typed attachments, and notes and suggestions.

## What's in 0.7.0

- **`docs/SECURITY.md`.** Threats T1 to T16, each with its defence, the test that proves it, and what the defence costs; the budgets and what happens at each; what report-err cannot defend against; how to report a vulnerability.
- **Attack tests.** One per threat (`tests/attack.rs` and the tests next to the code they cover): a million layers, 10,000 large attachments, a secret canary that must never print, a `Display` that panics, fails, writes 100 MiB, or never stops, a flood from 64 threads, a root whose `drop` panics, a full tree on a 64 KiB stack, terminal escapes and forged report lines, and an allocation failure in a child process.
- **Fuzzing.** Three cargo-fuzz targets: `ops` runs operation sequences and checks the invariants after every step, `display_adversary` renders errors whose `Display` misbehaves where the fuzzer chooses, and `limits` runs arbitrary budgets. Each ran 24 hours under AddressSanitizer with nothing found (`ops` in two parts: a clock change on the test machine stopped it at 22 hours); each runs 60 seconds in CI.
- **Soak.** 8 hours of 64 threads doing every operation, the second half with a creation hook and a reporter installed. The soak counts its live heap bytes exactly: they stayed flat and returned to within 7.7 KB of their start after 19.4 billion rounds on Windows and 3.0 billion on Linux.

## Fixed

- A `Display` that writes until its writer fails no longer hangs `render`, `ExitReport`, or the report. Both output caps now fail every write once full, and the report's repeat check stops copying a cause past `max_render`.
- The same `Display` no longer hangs `note`, `warning`, `suggestion`, or a field added by the creation hook: the byte budget's writer also fails once full.
- The source archives GitHub attaches to a release now build: they include `tests/`, which `Cargo.toml` names.

## Performance

The new limits apply only where report-err promises to stop a misbehaving `Display`: `render`, `record`, and `ExitReport`. `{}`, `{:#}`, and `{:?}` run 0.6.0's code; against 0.6.0 on one machine, `{}` is 7% faster and `{:#}` and `{:?}` are within 3%. The benchmark gate now measures the base branch and the change in turn, three rounds each, on the same runner, and fails a change that is more than 5% slower in all three, so noise on shared CI machines no longer fails a pull request.

## Verified

- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows on every unit and integration test.
- AddressSanitizer on every test, on Linux nightly.
- The full gate on Windows and Linux, stable and Rust 1.81.

## Installation

```toml
[dependencies]
report-err = "0.7.0"
```

Rust 1.81 or newer. `no_std` with `alloc` works with `default-features = false`.
