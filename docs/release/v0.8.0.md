# report-err v0.8.0 - Simpler API

**One way to do each thing.** v0.8.0 removed the methods that only repeated another way of doing the same thing, gave two items plainer names, and rewrote the API reference as a tour by task whose every example is compiled and run.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). It adds error codes with severity, category, and exit codes from define-err, a propagation trail, typed attachments, and notes and suggestions.

## What's in 0.8.0

- **Plainer names.** `unraisable` is now `report_unhandled`: it reports an error that has nowhere to go, as unhandled, and pairs with `Error::report`. `Error::with_kind` is now `with_kinds`, since it always took a set of kinds.
- **Fewer ways to do the same thing.** Six methods that only repeated another were removed: `Error::with_note`, `with_warning`, and `with_suggestion` (use `note`, `warning`, and `suggestion`; the lazy forms stay on `Context`), `Error::into_std` (use `.into()`), `Errors::finish_with` (use `finish`, then `Ok`), and `Error::find_in_suppressed` (a one-line `find_map` over `suppressed()`). The anyhow names stay, so moving from anyhow is still a change of crate name.
- **The API reference, by task.** `docs/API.md` covers every public item, task by task, and `cargo test` compiles and runs every example in it.
- **define-err 0.9.** report-err used define-err 0.5. An application that uses define-err 0.9 directly now gets one `Code`, `Severity`, `Category`, and `Kinds`, not two copies that do not convert.
- **As fast with define-err 0.9.** define-err 0.9 inlines its identity probe, which made `chain()` and reading a code set by hand slower under link-time optimisation. Both now keep their fast paths explicitly; against 0.7.0 on Linux, `chain()` is 5% to 30% faster (by depth) and a code found in the chain about 40% faster.

## Moving from 0.7

Each change is a compile error at the old name; `docs/MIGRATING.md` ("From report-err 0.7 to 0.8") has the replacement for each and a find-and-replace pass. Without a reporter, `report_unhandled` writes a line starting `Error (unhandled): ` where `unraisable` wrote `Error (unraisable): `.

## Verified

- The full gate on Windows and Linux, stable and Rust 1.81.
- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows, and AddressSanitizer, on every test, in CI.
- The benchmark gate against 0.7.0, base and head measured in turn three times on each platform.

## Installation

```toml
[dependencies]
report-err = "0.8.0"
```

Rust 1.81 or newer. `no_std` with `alloc` works with `default-features = false`.
