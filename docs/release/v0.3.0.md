# report-err v0.3.0 - The anyhow surface

**One error type for any error, in one machine word, with the names anyhow users already write.** v0.3.0 built the core: `Error`, `Result`, `Context` on `Result` and `Option`, `err!`, `format_err!`, `bail!`, `ensure!`, downcasting, the cause chain, the formatting rules, and conversion to and from `Box<dyn Error>`. An `Error` dereferences to `dyn Error`, and every context layer is a link of its `source()` chain.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). From `0.4.0` it adds error codes with severity, category, and exit codes, a propagation trace, typed attachments, and notes and suggestions; from `0.5.0` several causes, suppressed errors, and a panic boundary.

## What's in 0.3.0

- `Error`: `size_of::<Result<(), Error>>()` is one word, the same as anyhow; `Send + Sync + Unpin + UnwindSafe + RefUnwindSafe + 'static`. `Error::new`, `Error::msg`, and `From<E>` (what `?` calls) record where the error was created.
- Context: the first layer costs no allocation and layers two to five share one block; a literal is stored as is and a `String` is moved in, never copied; 64 layers are kept, and past that the oldest middle layers are dropped and counted.
- `Deref`, `DerefMut`, and `AsRef` to `dyn Error`: each layer links to the next, so a hand-written `source()` walk sees every layer, then the root and its sources, exactly as `chain()` does.
- `downcast_ref`, `downcast_mut`, `downcast`, `is`, `chain()`, `root_cause()`, `location()`.
- `Context::context` and `with_context` on `Result<T, E>`, `Result<T, Error>`, and `Option<T>`.
- `err!`, `format_err!`, `bail!`, `ensure!`; `ensure!(cond)` reports `condition failed: <cond>`.
- Formatting: `{}`, `{:#}` (the chain on one line, with a layer skipped when the one before it already ends with its text), `{:?}` (anyhow's report followed by `Location:`), `{:#?}`. None of them allocates.
- `into_std`, `from_boxed`, and `From<Error>` for the three `Box<dyn Error ...>` forms.

## Measured

Against anyhow 1.0.104 with criterion (Windows 11, AMD Ryzen 9 9950X3D, system allocator; every figure in `dev/PLAN.md` section 11.4):

| | report-err | anyhow |
|---|---|---|
| `?` then `.context("...")` | 26.7 ns | 52.3 ns |
| create plus 3 / 9 contexts | 65.6 / 125.5 ns | 110.5 / 409.1 ns |
| drop of an error with 3 contexts | 26.3 ns | 51.6 ns |
| `downcast_ref` to the root after 3 contexts | 1.01 ns | 2.47 ns |
| hand-written `source()` walk, 9 layers | 13.7 ns | 16.8 ns |
| `{:#}` of an error with 3 contexts | 54.7 ns | 27.3 ns |
| success path through 5 `?` | 4.96 ns | 4.85 ns |

`{:#}` was slower because of the de-duplication rule; it is recorded as an exception and revisited in the 0.6 optimisation milestone. The allocation counts are exact and tested: one for an error with its first context layer, two for three or five layers (anyhow: two, four, six).

## Verified

- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows, and AddressSanitizer, on every unit and integration test; Miri found one ordering bug in the context store during development, fixed before the release and covered by a test.
- A parity suite of 27 programs run against anyhow gave identical `{}`, `{:#}`, chain, root cause, `source()` walk, and downcast results; the designed differences are asserted as differences.
- A trial migration of kraken (a compiler) by find-and-replace changed 36 source lines with no hand edits and gave the same test results as with anyhow.
