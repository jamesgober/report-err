# report-err v0.5.0 - Feature complete

**Every planned feature is in.** v0.5.0 adds several causes and `collect_all()`, suppressed errors and cleanup, budgets on everything that grows, the panic boundary, the creation hook, reporting and records through define-err's facade, and a guarded renderer for paths that must not fail.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). It adds error codes with severity, category, and exit codes from define-err, a propagation trail, typed attachments, and notes and suggestions.

## What's in 0.5.0

- Several causes: `Error::group`, `children`, `push_child`, `split`, `flatten`, `Errors`, and `collect_all()`, which keeps every failure of an iterator, not only the first. The report shows them as a tree under `Causes (n):`.
- `find`, `find_all`, `find_in_suppressed`: search the whole tree, depth first, without allocating.
- Suppressed errors: `suppress`, `with_cleanup` (run a cleanup either way and keep both failures), and `unraisable` for an error with nowhere to go.
- Budgets: `Limits` and `configure`, set once, every field checked first.
- The panic boundary: `boundary`, `run`, `Error::from_panic`. A panic becomes an error with exit code 101 when panics unwind; `PANICS_CAUGHT` says whether they do.
- Reporting: `report` (once, from any thread), `record`, and the creation hook, whose fields print under `Fields:`.
- `render`: `{}`, `{:#}`, or `{:?}`, where a `Display` that panics or fails cannot stop the output.
- `testing`: `assert_chain_contains`, `assert_code`, `assert_section`.

## Bounded

A tree holds at most 1,024 errors and 16 levels by default, children and suppressed errors alike, so an error cannot grow without bound and dropping one cannot overflow the stack. `collect_all()` over 10,000,000 failures keeps 1,023 of them and counts all.

## Verified

- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows on every unit and integration test.
- AddressSanitizer on every test, including the process checks of `ExitReport` and `run`.
- `panic = "abort"`: a CI job builds an example with it and checks that the process aborts.
- A full tree at the depth limit is dropped on a thread with a 64 KiB stack.

## Installation

```toml
[dependencies]
report-err = "0.5.0"
```

Rust 1.81 or newer. `no_std` with `alloc` works with `default-features = false`.
