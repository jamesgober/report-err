# report-err v0.8.1 - Review fixes

**Fixes from an independent review of 0.8.0.** Upgrade from any earlier version: one fix is a soundness bug reachable from safe code. No API changed, so nothing in your code needs to change.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). It adds error codes with severity, category, and exit codes from define-err, a propagation trail, typed attachments, and notes and suggestions.

## What's in 0.8.1

- **Soundness: `DerefMut` on a boxed root.** For an error made by `Error::from_boxed`, or by `err!` on a boxed error, with no context layer, `&mut *error` wrote to the boxed error through a pointer made from a shared reference. That is undefined behaviour, and Miri reports it under both Stacked Borrows and Tree Borrows. The pointer is now made without a reference, and a Miri test covers the path.
- **Control characters escaped in `{:?}` and `render`.** The report that `fn main() -> Result<()>` prints, and `render`, now write terminal controls and Unicode bidirectional controls as `\u{..}` text, so text from outside (a file name, a header) cannot retitle the terminal, clear it, or rewrite a line. Newlines stay; `ExitReport` also indents continuation lines, so use it where an attacker controls the text. `{}` and `{:#}` are unchanged.
- **Public text never from a forged probe.** Any error's `description()` can claim to be a define-err error, and on Rust 1.81 to 1.89 std's string errors return their message from it. A variant's `#[public]` text is now used only from a catalog entry or a `from_info` root, so a relayed message cannot choose the text a client sees. `public_message()` and `record().public` now always agree.
- **Filtered reports cost nothing.** `report()` checks define-err's minimum severity and kinds mask before it builds the record.
- **One define-err per build.** report-err 0.7.0 and earlier depend on define-err 0.5 or older; beside an application on define-err 0.9, their reports and creation hook go to a copy the application never set up. `docs/SECURITY.md` now supports 0.8.x only, and CI fails when a build graph holds two define-err versions.

## Verified

- The full gate on Windows and Linux, stable and Rust 1.81.
- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows, and AddressSanitizer, in CI; the new Miri test fails on 0.8.0 under both models.
- The benchmark gate against 0.8.0, base and head measured in turn three times on each platform.

## Installation

```toml
[dependencies]
report-err = "0.8.1"
```

Rust 1.81 or newer. `no_std` with `alloc` works with `default-features = false`.
