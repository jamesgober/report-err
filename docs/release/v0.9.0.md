# report-err v0.9.0 - define-err 0.10

**On define-err 0.10.** report-err now builds on define-err 0.10, whose identity probe outside text can no longer forge, and which refuses a second copy of itself in one build. No name changed.

## What is report-err?

<strong>report-err</strong> gives application code one error type that holds any error, gathers context as it travels up the stack, and prints a clear report when it reaches `main`. Moving from anyhow is a change of crate name (and `anyhow!` becomes `err!`). It adds error codes with severity, category, and exit codes from define-err, a propagation trail, typed attachments, and notes and suggestions.

## What's in 0.9.0

- **define-err 0.10.** On Rust 1.81 to 1.89, std's string errors return their message from `description()`, so a peer's message relayed as `io::Error::other(text)` could pass for a defined error and claim any code, category, severity, and kinds. define-err 0.10 refuses such a probe, and report-err's test for it runs on Rust 1.81 in CI. The check costs about 10 to 15 ns each time a code or severity is read from an error found in the chain; a code set with `coded` costs what it did. define-err 0.10 also makes a second copy of itself a build error, so an application can no longer end up reporting into a copy nobody set up.
- **`report()` marks only what a reporter received.** With no reporter installed, `report()` now returns `false` and leaves the error unmarked, so an error reported at start-up, before `set_reporter`, can still be reported once a reporter is installed.
- **Indexed catalogs.** `configure_catalogs` indexes the catalogs once and finds a code by binary search, instead of scanning every entry on each lookup. Two entries with the same code are refused with `ConfigureError::DuplicateCode`, naming both types, instead of the first one answering silently.

## Moving from 0.8

In `Cargo.toml`, use `report-err = "0.9"`, and `define-err = "0.10"` if you depend on define-err directly. `docs/MIGRATING.md` ("From report-err 0.8 to 0.9") lists the three changes of behaviour.

## Verified

- The full gate on Windows and Linux, stable and Rust 1.81.
- Miri with `-Zmiri-strict-provenance` under Stacked Borrows and Tree Borrows, and AddressSanitizer, in CI.
- The benchmark gate against 0.8.1, base and head measured in turn three times on each platform.

## Installation

```toml
[dependencies]
report-err = "0.9.0"
```

Rust 1.81 or newer. `no_std` with `alloc` works with `default-features = false`.
